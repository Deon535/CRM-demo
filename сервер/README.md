# Сервер демо-CRM: памятка

Серверная часть (бэкенд). Раздаёт экран из папки `../приложение/` и отвечает на вопросы API (адреса `/api/...`). Устройство и шаги: `../план-этап-3.md`.

## Как запустить (на своём компьютере)

В терминале, находясь в папке `сервер/`:

- `npm install` — один раз: скачать готовые детали (Fastify и др.) в папку `node_modules/`.
- `npm start` — запустить сервер. В окне появятся строки журнала, окно занято, пока сервер работает.
- Открыть в браузере `http://localhost:3000` — это приложение, но уже с сервера.
- Открыть `http://localhost:3000/api/health` — ответ «сервер жив» (`ok: true`).
- `Ctrl+C` в том же окне — остановить сервер.
- `npm run dev` — то же, что `npm start`, но сервер сам перезапускается, когда вы правите его файлы.

Порт и адрес меняются переменными `PORT` и `HOST` (по умолчанию 3000 и `127.0.0.1`: сервер доступен только с этого компьютера).

## База данных (SQLite)

Файл базы: `data/crm.db` (создаётся сам при первом запуске, в git не попадает).

- `npm run db:reset` — **удалить базу и создать заново с демо-данными** (4 магазина и склад). Перед удалением переспрашивает, надо написать «да». Так делается «сброс демо».
- `npm run db:migrate` — применить новые миграции, ничего не стирая. Сервер делает то же самое сам при каждом запуске.
- Посмотреть содержимое можно бесплатной программой-просмотрщиком SQLite: таблицы видны как в Excel.

В Windows PowerShell вместо `npm` пишите `npm.cmd`.

## Вход и роли

Вход по логину и ПИН (4–6 цифр). После входа сервер выдаёт «пропуск» на 12 часов (cookie `crm_session`). После 5 неверных ПИН подряд вход блокируется на 15 минут. ПИН хранится только необратимым отпечатком (хэшем).

Адреса: `POST /api/login`, `POST /api/logout`, `GET /api/me` (кто я и какие у меня права), `POST /api/me/pin` (сменить ПИН), `POST /api/staff` (создать сотрудника, только владелец), `POST /api/staff/:id/dismiss` («уволить»).

Демо-сотрудники (появляются после `npm run db:reset`): `magomed` (владелец), `ruslan` и `zaur` (старшие продавцы), `murad`, `ali`, `rashid`, `timur`, `kamil` (продавцы), `patimat` (онлайн-менеджер), `ismail` (курьер), `zarema` (бухгалтер). Один демо-ПИН на всех записан в `src/db/seed-demo.js` (строка `DEMO_PIN`). Только для демо.

На сервере за «ресепшеном» с HTTPS включить переменные `COOKIE_SECURE=1` и `TRUST_PROXY=1`.

## Автоматические проверки

`npm run test` — запускает проверки входа, прав и сотрудников на базе в памяти (настоящая база не затрагивается). Все должны быть зелёными.

## Что где лежит

- `package.json` — паспорт программы: название, команды запуска, список подключённых деталей.
- `src/app.js` — запуск сервера. `src/build-app.js` — сборка сервера (его же берут тесты).
- `src/auth/` — вход и права: `crypto.js` (хэш ПИН, пропуска), `cookies.js`, `auth.js` (вся логика входа, прав, сотрудников), `routes.js` (адреса API и «охранники» для будущих адресов).
- `tests/` — автоматические проверки.
- `src/db/db.js` — подключение к базе и запуск миграций.
- `src/db/seed-demo.js` — демо-данные (магазины и сотрудники).
- `src/db/migrations/` — миграции: пронумерованные файлы «как менялась база» (`0001-core.sql` и далее). Применённые файлы не правим, только добавляем новые.
- `src/db/seed-demo.sql` — демо-данные для `db:reset` (только для показа).
- `scripts/db.js` — команды `migrate` и `reset`.
- `data/` — файл базы. В git не попадает.
- `node_modules/` — скачанные детали, появляется после `npm install`. В git не попадает.

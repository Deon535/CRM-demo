## Что за проект
Пользователь учится делать системы с бэкендом и базами данных на примере CRM для магазинов одежды. Пример заказчика: «Магомед», 4 магазина мужской одежды в Дагестане (роль играл Claude). Цель демо: показывать его разным магазинам одежды, поэтому система универсальная (ядро + модули + настройки).

Правила: каждый адрес проверяет роль на сервере; закупочные цены сервер не отправляет тем, кому нельзя; «Продано» выполняется целиком как одна операция «всё или ничего» (транзакция). ПИН хранится только хэшем (логин как есть), после нескольких неверных попыток вход блокируется на время, только по HTTPS. Сотрудников создаёт только владелец («Люди / Новый сотрудник»): сервер выдаёт логин и временный ПИН, при первом входе сотрудник меняет ПИН; первый владелец создаётся при установке. Пропуск (сессия) выдаётся при входе, хранится таблицей на сервере, номер лежит в cookie браузера; срок жизни решим в плане. Увольнение: сотрудника не удаляем (ТЗ 10.7), ставим пометку «не работает» и удаляем все его пропуска. Права: закрытый список прав пишем мы; роль = набор прав; 6 ролей приходят готовыми, владелец меняет переключатели («Настройки / Права ролей») и создаёт свои роли; у сотрудника записана только роль (права не копируются, изменение роли действует сразу на всех); отдельному человеку особых прав нет (нужна отдельная роль). Проверка двойная: право (что можно) + область (все магазины / свой магазин / только свои записи; магазин берётся из карточки сотрудника). Владельцу нельзя отобрать право менять права. В демо-режиме окно входа даёт выбрать роль без ПИН (ТЗ 13), в боевом выключается настройкой.

На сервере: «ресепшен» (обратный прокси, HTTPS), наша программа на Node.js, «сторож» (перезапуск при падении), файл SQLite на диске и ежедневные копии, файрвол.
